# Task Manager

A task management app with a FastAPI backend, SQLite-backed persistent storage, and a vanilla HTML/JS frontend. Tasks can be created, listed (with search, filtering, and sorting), viewed, updated, and deleted, and survive server restarts.

## Tech Stack

- **Backend:** Python, [FastAPI](https://fastapi.tiangolo.com/), [Pydantic](https://docs.pydantic.dev/), served via [Uvicorn](https://www.uvicorn.org/)
- **Frontend:** Static HTML, CSS, and vanilla JavaScript (no framework/build step), served by FastAPI's `StaticFiles`
- **Storage:** SQLite via [SQLAlchemy](https://www.sqlalchemy.org/) (file-backed, persists across restarts) — chosen over an in-memory store because the project needs durable single-user storage without the operational overhead of a standalone database server; SQLAlchemy maps cleanly onto the existing Pydantic models with a single added dependency.
- **Testing:** `pytest` with FastAPI's `TestClient` (via `httpx`)

See `PROJECT_SPEC.md` for the full design rationale.

## Setup / Install

Requires Python 3.10+ (uses `X | None` union type syntax).

```bash
pip install -r backend/requirements.txt
```

Dependencies: `fastapi`, `uvicorn[standard]`, `pytest`, `httpx`, `sqlalchemy`.

## Running the Application

From the project root:

```bash
uvicorn backend.main:app --reload
```

The app will be available at `http://127.0.0.1:8000`:
- `http://127.0.0.1:8000/` — serves the frontend (`frontend/index.html`)
- `http://127.0.0.1:8000/tasks` — the JSON API
- `http://127.0.0.1:8000/docs` — interactive Swagger UI (auto-generated by FastAPI)

On first run, `backend/tasks.db` is created automatically and all tables are set up. Data persists across restarts.

## Running Tests

From the project root:

```bash
pytest
```

Tests use FastAPI's `TestClient` against the app in-process (no server needs to be running) and reset the database (drop/recreate tables) before each test.

## Data Model

A `Task` has the following fields:

| Field         | Type                                  | Default    | Notes                                  |
|---------------|----------------------------------------|------------|-----------------------------------------|
| `id`          | `int`                                   | assigned   | Auto-incremented, set by the server     |
| `title`       | `string` (max 200 chars)               | required   | Must be non-empty after trimming whitespace |
| `description` | `string` (max 2000 chars)              | `""`       |                                          |
| `notes`       | `string` (max 2000 chars)              | `""`       |                                          |
| `completed`   | `boolean`                               | `false`    |                                          |
| `priority`    | `"low" \| "medium" \| "high"`           | `"medium"` |                                          |
| `due_date`    | `string ("YYYY-MM-DD") \| null`         | `null`     | Validated as an ISO calendar date        |
| `category`    | `"Work" \| "Study" \| "Personal" \| "Shopping" \| "Other"` | `"Other"` | Values are case-sensitive exact matches |
| `created_at`  | `datetime` (ISO 8601)                   | assigned   | Set by the server on creation; used for `sort_by=created` |

## API Endpoints

Base path: `/tasks`

### `GET /tasks`

List tasks, with optional search, filtering, and sorting via query parameters.

**Query parameters (all optional):**
| Param       | Type                              | Description                                      |
|-------------|-------------------------------------|---------------------------------------------------|
| `search`    | string                              | Case-insensitive substring match on `title` only  |
| `completed` | boolean                             | Filter by completion status                        |
| `priority`  | `"low" \| "medium" \| "high"`       | Filter by priority                                 |
| `category`  | `"Work" \| "Study" \| "Personal" \| "Shopping" \| "Other"` | Filter by category (exact match)   |
| `sort_by`   | `"title" \| "created"`              | Sort field (unsorted/insertion order if omitted)   |
| `order`     | `"asc" \| "desc"` (default `"asc"`) | Sort direction                                     |

- **Response:** `200 OK` — JSON array of `Task` objects
- **Errors:** `422 Unprocessable Entity` if `category`/`priority` is not a valid value

Example:
```bash
curl "http://127.0.0.1:8000/tasks?category=Study"
```
```json
[
  {
    "title": "Read chapter 3",
    "description": "",
    "notes": "",
    "completed": false,
    "priority": "medium",
    "due_date": null,
    "category": "Study",
    "id": 2,
    "created_at": "2026-08-20T10:00:00+00:00"
  }
]
```

### `POST /tasks`

Create a new task.

- **Request body** (`TaskCreate`): `title` (required, non-empty, ≤200 chars), `description`, `notes` (≤2000 chars each), `completed`, `priority`, `due_date` (`YYYY-MM-DD` or omitted), `category` (all optional with the defaults above)
- **Response:** `201 Created` — the created `Task` (including its assigned `id` and `created_at`)
- **Errors:** `422 Unprocessable Entity` if `title` is missing/empty/too long, `priority`/`category` is not a valid value, `due_date` isn't a valid `YYYY-MM-DD` date, or `description`/`notes` exceed 2000 characters

Example:
```bash
curl -X POST http://127.0.0.1:8000/tasks \
  -H "Content-Type: application/json" \
  -d '{"title": "Buy milk", "priority": "high", "due_date": "2026-09-01"}'
```
```json
{
  "title": "Buy milk",
  "description": "",
  "notes": "",
  "completed": false,
  "priority": "high",
  "due_date": "2026-09-01",
  "category": "Other",
  "id": 1,
  "created_at": "2026-08-20T10:00:00+00:00"
}
```

### `GET /tasks/{task_id}`

Fetch a single task by ID.

- **Response:** `200 OK` — the `Task` object
- **Errors:** `404 Not Found` if no task with that ID exists; `422 Unprocessable Entity` if `task_id` is not a positive integer

Example:
```bash
curl http://127.0.0.1:8000/tasks/1
```
```json
{
  "title": "Buy milk",
  "description": "",
  "notes": "",
  "completed": false,
  "priority": "high",
  "due_date": "2026-09-01",
  "category": "Other",
  "id": 1,
  "created_at": "2026-08-20T10:00:00+00:00"
}
```

### `PUT /tasks/{task_id}`

Partially update a task. Only the fields included in the request body are changed; omitted fields are left as-is.

- **Request body** (`TaskUpdate`): any subset of `title`, `description`, `notes`, `completed`, `priority`, `due_date`, `category`
- **Response:** `200 OK` — the updated `Task` object
- **Errors:** `404 Not Found` if no task with that ID exists; `422 Unprocessable Entity` if `task_id` is not a positive integer, `title` is present but empty/`null`/too long, `due_date` is malformed, or `priority`/`category` is invalid

Example — toggling completion:
```bash
curl -X PUT http://127.0.0.1:8000/tasks/1 \
  -H "Content-Type: application/json" \
  -d '{"completed": true}'
```
```json
{
  "title": "Buy milk",
  "description": "",
  "notes": "",
  "completed": true,
  "priority": "high",
  "due_date": "2026-09-01",
  "category": "Other",
  "id": 1,
  "created_at": "2026-08-20T10:00:00+00:00"
}
```

### `DELETE /tasks/{task_id}`

Delete a task by ID.

- **Response:** `204 No Content`
- **Errors:** `404 Not Found` if no task with that ID exists; `422 Unprocessable Entity` if `task_id` is not a positive integer

Example:
```bash
curl -X DELETE http://127.0.0.1:8000/tasks/1
```
(No response body; `204 No Content` on success.)

## Current Functionality

- Create tasks with a title, description, notes, priority, category, and optional due date
- List all tasks, with search, filtering (completion, priority, category), and sorting (title or creation time, ascending/descending)
- Fetch a single task by ID
- Update any subset of a task's fields
- Delete a task
- Data persists in a SQLite database (`backend/tasks.db`) and survives server restarts
- Minimal web UI (served at `/`) for adding, toggling completion, editing notes/due date, deleting, and searching/filtering/sorting tasks

### Known limitations

- No authentication or multi-user support
- No pagination (list endpoint returns all tasks)
- No rate limiting
- Concurrent-write conflict handling relies on SQLite's default locking (sufficient at this project's scale, not intended for high-concurrency use)
