# Task Manager

A simple in-memory task management app with a FastAPI backend and a vanilla HTML/JS frontend. Tasks can be created, listed (with search, filtering, and sorting), viewed, updated, and deleted.

## Tech Stack

- **Backend:** Python, [FastAPI](https://fastapi.tiangolo.com/), [Pydantic](https://docs.pydantic.dev/), served via [Uvicorn](https://www.uvicorn.org/)
- **Frontend:** Static HTML, CSS, and vanilla JavaScript (no framework/build step), served by FastAPI's `StaticFiles`
- **Storage:** In-memory Python dictionary (no database — data is lost on server restart)
- **Testing:** `pytest` with FastAPI's `TestClient` (via `httpx`)

## Setup / Install

Requires Python 3.10+ (uses `X | None` union type syntax).

```bash
pip install -r backend/requirements.txt
```

Dependencies: `fastapi`, `uvicorn[standard]`, `pytest`, `httpx`.

## Running the Application

From the project root:

```bash
uvicorn backend.main:app --reload
```

The app will be available at `http://127.0.0.1:8000`:
- `http://127.0.0.1:8000/` — serves the frontend (`frontend/index.html`)
- `http://127.0.0.1:8000/api/tasks` — the JSON API
- `http://127.0.0.1:8000/docs` — interactive Swagger UI (auto-generated by FastAPI)

## Running Tests

From the project root:

```bash
pytest
```

Tests use FastAPI's `TestClient` against the app in-process (no server needs to be running) and clear the in-memory `tasks` store before each test.

## Data Model

A `Task` has the following fields:

| Field         | Type                                  | Default    | Notes                                  |
|---------------|----------------------------------------|------------|-----------------------------------------|
| `id`          | `int`                                   | assigned   | Auto-incremented, set by the server     |
| `title`       | `string`                                | required   |                                          |
| `description` | `string`                                | `""`       |                                          |
| `notes`       | `string`                                | `""`       |                                          |
| `completed`   | `boolean`                               | `false`    |                                          |
| `priority`    | `"low" \| "medium" \| "high"`           | `"medium"` |                                          |
| `due_date`    | `string \| null`                        | `null`     | Free-form string (e.g. `"2026-09-01"`)  |
| `category`    | `"Work" \| "Study" \| "Personal" \| "Shopping" \| "Other"` | `"Other"` | Values are case-sensitive exact matches |

## API Endpoints

Base path: `/api/tasks`

### `GET /api/tasks`

List tasks, with optional search, filtering, and sorting via query parameters. Each `Task` in the response includes its `category`.

**Query parameters (all optional):**
| Param       | Type                              | Description                                      |
|-------------|-------------------------------------|---------------------------------------------------|
| `search`    | string                              | Case-insensitive substring match on `title` only  |
| `completed` | boolean                             | Filter by completion status                        |
| `priority`  | `"low" \| "medium" \| "high"`       | Filter by priority                                 |
| `category`  | `"Work" \| "Study" \| "Personal" \| "Shopping" \| "Other"` | Filter by category (exact match)   |
| `sort_by`   | `"title" \| "created"`              | Sort field (unsorted/creation order if omitted)    |
| `order`     | `"asc" \| "desc"` (default `"asc"`) | Sort direction                                     |

- **Response:** `200 OK` — JSON array of `Task` objects
- **Errors:** `422 Unprocessable Entity` if `category` is not one of `Work`/`Study`/`Personal`/`Shopping`/`Other`

Filters combine (e.g. `category` and `completed` together return only tasks matching both).

Example — filtering by category:
```bash
curl "http://127.0.0.1:8000/api/tasks?category=Study"
```
```json
[
  {
    "title": "Read chapter 3",
    "description": "",
    "notes": "",
    "completed": false,
    "priority": "medium",
    "due_date": null,
    "category": "Study",
    "id": 2
  }
]
```

### `POST /api/tasks`

Create a new task.

- **Request body** (`TaskCreate`): `title` (required), `description`, `notes`, `completed`, `priority`, `due_date`, `category` (all optional with the defaults above)
- **Response:** `201 Created` — the created `Task` (including its assigned `id`)
- **Errors:** `422 Unprocessable Entity` if `priority` is not one of `low`/`medium`/`high`, if `category` is not one of `Work`/`Study`/`Personal`/`Shopping`/`Other`, or if `title` is missing

Example:
```bash
curl -X POST http://127.0.0.1:8000/api/tasks \
  -H "Content-Type: application/json" \
  -d '{"title": "Buy milk", "priority": "high", "due_date": "2026-09-01"}'
```
```json
{
  "title": "Buy milk",
  "description": "",
  "notes": "",
  "completed": false,
  "priority": "high",
  "due_date": "2026-09-01",
  "category": "Other",
  "id": 1
}
```

Example — creating a task with an explicit category:
```bash
curl -X POST http://127.0.0.1:8000/api/tasks \
  -H "Content-Type: application/json" \
  -d '{"title": "Finish report", "category": "Work"}'
```
```json
{
  "title": "Finish report",
  "description": "",
  "notes": "",
  "completed": false,
  "priority": "medium",
  "due_date": null,
  "category": "Work",
  "id": 2
}
```

### `GET /api/tasks/{task_id}`

Fetch a single task by ID.

- **Response:** `200 OK` — the `Task` object
- **Errors:** `404 Not Found` if no task with that ID exists

### `PUT /api/tasks/{task_id}`

Partially update a task. Only the fields included in the request body are changed; omitted fields are left as-is.

- **Request body** (`TaskUpdate`): any subset of `title`, `description`, `notes`, `completed`, `priority`, `due_date`, `category`
- **Response:** `200 OK` — the updated `Task` object
- **Errors:** `404 Not Found` if no task with that ID exists; `422 Unprocessable Entity` if `category` (or `priority`) is not a valid value

Example — toggling completion:
```bash
curl -X PUT http://127.0.0.1:8000/api/tasks/1 \
  -H "Content-Type: application/json" \
  -d '{"completed": true}'
```

Example — updating a task's category:
```bash
curl -X PUT http://127.0.0.1:8000/api/tasks/1 \
  -H "Content-Type: application/json" \
  -d '{"category": "Personal"}'
```

### `DELETE /api/tasks/{task_id}`

Delete a task by ID.

- **Response:** `204 No Content`
- **Errors:** `404 Not Found` if no task with that ID exists

## Current Functionality

- Create tasks with a title, description, notes, priority, category, and optional due date
- List all tasks
- Search tasks by title (case-insensitive substring match)
- Filter tasks by completion status, priority, and/or category
- Sort tasks by title or creation order, ascending or descending
- Fetch a single task by ID
- Update any subset of a task's fields (including toggling `completed`, editing notes, changing/clearing the due date, and changing category)
- Delete a task
- Minimal web UI (served at `/`) for adding tasks (including choosing a category, default `Other`), toggling completion by clicking the title, editing/saving notes and due date per task, deleting tasks, and searching/filtering (by completion, priority, and category)/sorting the list

### Known limitations

- Data is stored **in memory only** — all tasks are lost when the server restarts; there is no database or persistence layer
- No authentication or multi-user support
- `due_date` is stored as a plain string with no date-format validation
- The frontend's "sort by" control only offers `title` (the API also supports sorting by `created`)
